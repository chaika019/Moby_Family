# Moby Family — frontend

React + TypeScript + Vite. На компьютере видны экраны родителя и ребёнка, на телефоне роли переключаются. Все деньги в приложении виртуальные; банковские операции не выполняются.

## Запуск

Из корня репозитория запустите backend, затем frontend:

```bash
./mvnw spring-boot:run
cd frontend
npm ci
npm run dev
```

Vite откроется на `http://localhost:5173` и проксирует `/api` на backend `http://localhost:8080`. На первом экране можно войти в серверный режим или открыть локальное демо. Для единого JAR используйте `./scripts/build-app.sh` из корня репозитория.

`npm run build` проверяет TypeScript, создаёт `dist/`, автономный `Moby-preview.html` и SVG/PNG QR-чеков в `public/demo-qr/`. Для просмотра автономного демо откройте `Moby-preview.html` в браузере. Камера работает при HTTPS или localhost и требует разрешения браузера; если доступ недоступен, доступны три демо-чека.

## QR-оплата

Сканер принимает JSON с полями `merchant`, `mcc`, `amount`, `items` (`name`, `price`). Итог чека должен точно совпадать с суммой позиций. Считанный чек и демо-кнопки проходят один путь оплаты. В серверном режиме запрос идёт на `POST /api/v1/qr-payment/scan`; после ответа состояние семьи перечитывается. Демо-чек супермаркета на 52 BYN создаёт SOS на недостающие 7 BYN при стартовом балансе ребёнка 45 BYN.

Готовые QR-коды для показа на другом экране или печати: `public/demo-qr/buffet`, `sos`, `blocked` в форматах SVG и PNG.

## Проверка

```bash
npm test
npm run build
npm run test:e2e
```

Playwright проверяет desktop 1440×1200, iPhone 393×852 и Samsung 360×800. Для установленного отдельно Chromium можно указать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Физическую камеру конкретного устройства следует проверить перед показом.

В `docs/PROJECT_NOTES.md` записаны подробности сценариев, ограничений и проверок.
