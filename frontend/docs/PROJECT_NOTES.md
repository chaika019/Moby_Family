## Визуальное направление
Электрический синий Moby, белые поверхности, мягкий сиреневый и оранжевый акцент; просторная типографика, большие зоны касания, нижняя навигация в зоне большого пальца. Ребёнок: дружелюбный лис, мечта, прогресс и награды. Родитель: спокойный обзор, ребёнок и доступные действия, контекстные подтверждения. Лис используется как CSS-фрагмент предоставленного референса; отдельного исходника маскота нет.

## Архитектура и границы
Frontend создан с нуля: исходная папка содержала только references. src/lib/demo.ts — единое локальное состояние и команды, src/lib/api.ts — изолированный fetch-клиент, src/App.tsx — экраны/сценарии, src/styles.css — адаптивная дизайн-система. Демо сохраняется в localStorage, восстанавливается/сбрасывается через панель; вкладки синхронизируются storage event.

Backend DTO уже прочитан в api/Api.java. FamilyState содержит family, children[].profile/spendingRules/chores/piggyBanks/capital18/transactions/shop/academy, benefits, qrPresets. Авторизация Bearer /api/v1/auth/login, GET /api/v1/family/state. Vite проксирует /api на localhost:8080. Не хранить пароль; access token только в памяти. Реальная банковская интеграция отсутствует, серверные возможности зависят от параллельной реализации.

## Подключение к backend

Реальной интеграции с МТБанком нет, деньги виртуальные.

Backend собирается вместе с frontend командой `./scripts/build-app.sh`, результат `target/mobyfamily-0.0.1-SNAPSHOT.jar`; для разработки Vite проксирует `/api` на Spring Boot. ## Сканер QR-чеков, 21 октября 2026

В Moby Junior окно QR-оплаты теперь включает камеру через html5-qrcode, проверяет JSON чека (магазин, MCC, итог, позиции, суммы в копейках) и отправляет считанный чек на `/api/v1/qr-payment/scan` с UUID ребёнка и ключом идемпотентности. Три демо-кнопки используют тот же путь: буфет 4,50 BYN, супермаркет 52 BYN с SOS на 7 BYN и игровой MCC 7994 для проверки блокировки. Управление игровыми категориями по-прежнему отсутствует в разделе «Где можно тратить»; игровой чек служит только проверкой защиты. Камера освобождается при закрытии окна, при отказе доступа остаются демо-кнопки. Физическая камера требует HTTPS или localhost; локальное автономное HTML-демо пользуется кнопками, если камера недоступна.

Сборка создаёт готовые SVG и PNG QR-коды в `public/demo-qr/`; ссылки на SVG внутри приложения доступны и в автономном HTML. Проверено: 28 доменных/парсерных/серверных контрактных frontend-тестов, 21 браузерный сценарий на desktop, 393×852 и 360×800, production build. Дополнительная проверка через Chromium с искусственным видеопотоком из `sos.png` подтвердила настоящее распознавание и открытие SOS. Реальную физическую камеру и разрешения конкретного телефона надо проверить на устройстве при показе.
