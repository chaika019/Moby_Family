# Moby Family backend

Самостоятельное семейное приложение с виртуальными деньгами: родитель и ребёнок, QR-оплаты и SOS, задания, копилки, академия и долгосрочный план накоплений. Клиент находится в `frontend/` и работает с этим API: вход родителя/ребёнка, семейные экраны и действия используют серверные данные. Подключения к Moby/МТБанку нет; все средства виртуальные.

## Запуск

Нужны JDK 21 и Node.js/npm. Для единого приложения, где backend раздаёт frontend, используйте:

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
./scripts/build-app.sh
java -jar target/mobyfamily-0.0.1-SNAPSHOT.jar
```

Сервер: `http://localhost:8080`; Swagger: `http://localhost:8080/swagger-ui/index.html`.

По умолчанию профиль `standalone`: встроенная H2 сохраняет данные в `./data/moby` между перезапусками. `data/` исключена из Git. Для разработки отдельно запустите backend (`./mvnw spring-boot:run`) и frontend (`cd frontend && npm ci && npm run dev`); Vite проксирует `/api` на `localhost:8080`. Автономное демо фронта остаётся доступно кнопкой на экране входа.

Вход родителя: **parent@moby.local / demo-parent-2026!**. Начальная семья: Алексей, Никита 11 лет и Макс 15 лет. Сиды создаются один раз, повторный запуск их не перезаписывает. `demo` — те же данные в памяти, сбрасываются при перезапуске:

```bash
./mvnw spring-boot:run -Dspring-boot.run.profiles=demo
./mvnw verify
```

## Вход и первые действия

1. `POST /api/v1/auth/login` с `{"email":"parent@moby.local","password":"demo-parent-2026!"}`.
2. Передавать `Authorization: Bearer <accessToken>`. Токен действует один час. В автономном режиме ключ генерируется при старте, после перезапуска нужно войти снова.
3. `GET /api/v1/family/state` возвращает семью и `children[]` с UUID, настройками, заданиями, копилками, вкладом, транзакциями, магазином и академией.
4. `POST /api/v1/parent/children/{childId}/login-qr` выдаёт QR-токен на 5 минут. `POST /api/v1/auth/qr-login` с `{"qrAuthToken":"..."}` обменивает его на JWT ребёнка ровно один раз. QR содержит секрет, не записывайте его в логи и URL.
5. Новую семью можно создать через `/auth/register` (`email`, `password`, `familyName`), ребёнка — `/onboarding/child` (`firstName`, `age`, необязательные `birthDate`, `birthCertScanBase64`). Скан проверяется на Base64 и не сохраняется; проверки личности нет.
6. Для новой семьи в standalone/demo доступно `POST /parent/wallet/fund` с `{"amount":100}`: это добавление **виртуальных** средств, без платёжной системы. В `postgres` функция по умолчанию выключена.

Все пути ниже начинаются с `/api/v1`. Для команд нужен **Idempotency-Key**: уникальная строка из 8–100 букв, цифр, `_` или `-`. При сетевом повторе используйте прежний ключ и то же тело: списание не повторится. Для нового действия нужен новый ключ. Повторное применение ключа к другому действию даёт `409 IDEMPOTENCY_CONFLICT`. Вход, onboarding и выдача login-QR не используют этот заголовок.

## Возможности API

| Сценарий | Endpoint |
| --- | --- |
| Состояние семьи | `GET /family/state` |
| История ребёнка | `GET /children/{childId}/transactions?page=0&size=50` |
| QR-оплата | `POST /qr-payment/scan` |
| Подтвердить / отклонить SOS | `POST /sos/{id}/approve`, `/reject` |
| Пополнить карту ребёнка | `POST /parent/top-up` |
| MCC, дневной/месячный лимит, безопасность | `PATCH /parent/mcc-rules`, `/parent/limits`, `/parent/safety-settings` |
| Заморозка / демонстрационная карта | `POST /parent/card-freeze`, `/parent/cards` |
| Приватность подростка | `PATCH /children/privacy` |
| Создать задание | `POST /chores` |
| Отправить / подтвердить / отменить задание | `POST /chores/{id}/submit`, `/approve`, `/cancel` |
| Создать / пополнить копилку | `POST /piggy`, `/piggy/{id}/deposit` |
| Настроить Капитал 18 | `POST /deposits/capital18/configure` |
| Пополнение вклада со счёта родителя | `POST /deposits/capital18/{id}/gift` |
| Принять взрослый пакет после 18 лет | `POST /deposits/capital18/{id}/adult-package` |
| Публичные сведения для подарка | `GET /public/gifts/{token}` |
| Разделить счёт / оплатить долю | `POST /social/split-bill`, `/social/split-bill/{id}/pay` |
| Поездка домой за счёт родителя | `POST /safety/panic-ride` |
| Пройти урок | `POST /gamification/quiz-complete` |
| Купить / активировать награду | `POST /gamification/shop/{id}/buy`, `/activate` |
| Добавить родительскую награду | `POST /parent/rewards` |
| Карманные по расписанию | `POST /parent/allowances`, `/parent/allowances/{id}/stop` |
| Подписка | `POST /parent/subscription/true` или `/false` |

Полные поля и типы доступны в Swagger и `api/Api.java`. Денежные значения — BYN, максимум два знака после запятой; Moby Coins хранятся отдельно.

### QR и SOS

```json
{
  "childId": "UUID ребёнка",
  "merchantName": "Школьный буфет",
  "mccCategory": "5814",
  "amount": 4.50,
  "receiptItems": [{"title":"Обед","quantity":1,"unitPrice":4.50}],
  "secretGiftMode": false,
  "countryCode": "BY",
  "online": false
}
```

`mccCategory` — четыре цифры. Для настройки MCC применяются `GAMING_7994`, `FASTFOOD_5814`, `CASH_6011`, `ADULT_18_PLUS`, `NIGHT_SPEND`. Ночные запреты действуют 22:00–07:00 Europe/Minsk. Проверяются заморозка, MCC, дневной и месячный лимит, онлайн- и географические ограничения. Непустой чек должен сходиться по сумме.

При нехватке денег возвращается `NEED_SOS_TOPUP`, `id` SOS и `missingAmount`. Запрос действует 10 минут. Подтверждение родителем заново проверяет ограничения и в одной транзакции переводит актуальную недостающую сумму и оплачивает исходный чек. Кешбэк 5% за успешную QR-оплату начисляется при активной подписке.

В исходном ТЗ дневной лимит 20 BYN противоречил SOS-пресету на 52 BYN. В начальном профиле Никиты лимит 100 BYN, поэтому все три пресета воспроизводятся.

### Задания и накопления

Создание задания резервирует награду на родительском счёте; эти деньги нельзя потратить на другие операции. Выплата разрешена только после отправки на проверку, повторное подтверждение не платит второй раз. Отмена освобождает холд.

Пополнение копилки списывает взнос ребёнка и процент матчинга родителя атомарно. Прогресс соперника в начальных данных демонстрационный, он не подключён к чужому банковскому аккаунту.

Капитал 18 рассчитывается при 11,5% годовых, ежемесячной капитализации и взносах в конце месяца. Расчёт выполняется формулой, а не заданными в ТЗ противоречивыми итоговыми числами. Минимум для разового плана — 2000 BYN, для ежемесячного — 500 BYN. Повторная настройка не списывает стартовый взнос заново. Два ежемесячных платежа списываются из одного семейного кошелька; отдельных зарплатных карт родителей нет.

Ежемесячные взносы поступают в буфер, который тоже капитализируется; раз в 37 месяцев он объединяется с основной суммой. Прогноз предполагает постоянную ставку и все будущие взносы, грант в него не включён. После более 36 последовательных взносов устанавливается право на 200 BYN при совершеннолетии и принятии взрослого пакета. Публичная ссылка раскрывает только имя ребёнка и доступность пополнения: анонимного начисления средств и ЕРИП нет. Зачисление подарка через API доступно родителю из его семейного кошелька.

Планировщик раз в минуту обрабатывает подписку, карманные, капитализацию, пролонгацию и истечение SOS. Выполненные периоды защищены сохранёнными датами. При недостающем балансе ежемесячный взнос/карманные пропускаются с событием, без ухода в минус. Это модель накоплений, не банковский вклад и не юридические условия продукта.

### Академия и магазин

Сначала получите вопросы из `children[].academy`. В `/gamification/quiz-complete` передавайте `childId`, `quizId`, `answers` (индексы вариантов с нуля). Поле `score` из ТЗ принимается, но **не определяет награду**: сервер проверяет ответы сам. Уроки открываются последовательно, +100 Coins выдаются один раз. В магазине владение хранится отдельно для каждого ребёнка, цена берётся с сервера. Купленные скины и звуки активируются; родительский приз отображается как приобретённая награда.

Split bill с `payerChildId` переводит долю от другого ребёнка **этой же семьи**. Запрос с одним `friendName` — только сохранённая договорённость, без доступа к внешнему кошельку друга.

### События

`GET /family/events` — SSE с Bearer-токеном. Событие `ready` просит обновить `/family/state`; после него приходят `family-update` с монотонным `id`. При переподключении передайте `Last-Event-ID`. Сервер хранит события в БД и отправляет только после commit; ребёнок видит свои события, родитель — семейные. Payload содержит тип и ID, без чеков и персональных деталей покупок. Heartbeat раз в 15 секунд. При истечении JWT поток закрывается.

Для браузера нужен `fetch` с чтением потока либо SSE-клиент, умеющий `Authorization`: обычный `EventSource` не принимает произвольные заголовки. Токен в URL передавать не следует. После события перечитывайте состояние: сервер фильтрует приватность для конкретной роли.

## PostgreSQL и Docker

Миграция `V1__family_schema.sql` используется и H2, и PostgreSQL; Hibernate запускается с `ddl-auto=validate`.

```bash
export DB_PASSWORD='your-local-password'
export JWT_SECRET='replace-with-a-random-secret-at-least-32-bytes'
docker compose up -d
SPRING_PROFILES_ACTIVE=postgres ./mvnw spring-boot:run
```

`DB_URL` по умолчанию `jdbc:postgresql://localhost:5432/moby`, `DB_USER=moby`. В postgres не создаётся демонстрационная семья, но создаётся каталог наград. Регистрация создаёт пустой семейный кошелёк. Статический секрет JWT обязателен. Образ backend можно собрать через `docker build -t moby-family .`; файл `Dockerfile` не включает frontend.

## Границы текущей версии

- Все расчёты и движения средств выполняются внутри приложения. Эквайринг, выпуск настоящих карт, ЕРИП, проверка документов, страховые договоры и такси не подключены.
- Panic Ride регистрирует запрос и списывает виртуальные 12 BYN с родителя; автомобиль не заказывается. Страхование и Халва представлены каталогом концепций.
- Маскот — выбираемый образ и учебные подсказки, без внешнего LLM. Звук и внешний вид воспроизводит frontend.
- CORS разрешает `/api/**` для любого origin без cookie; аутентификация — Bearer. Есть проверки роли, семьи и владельца ребёнка. Секретные подарки и подростковая приватность скрывают продавца, MCC и позиции в ответах родителю.
- Транзакции сериализуются блокировкой строки семьи. Семейный кошелёк — модель приложения, без банковского ledger/сверки с процессингом. Интеграцию с Moby следует реализовывать отдельным адаптером с проверенными контрактами банка.
- Frontend использует серверные команды с ключами идемпотентности, обновляет состояние по SSE и резервному опросу. Локальное демо отдельно от серверного режима.
